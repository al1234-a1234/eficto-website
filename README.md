# إفيكتو | eficto

موقع مطعم إفيكتو (بريدة) — واجهة عامة (Next.js App Router + Tailwind، عربي RTL) بالإضافة إلى لوحة تحكم داخلية للحجوزات وقائمة الانتظار وCRM، مبنية على Supabase (Postgres + Auth + Realtime).

## الستاك

- Next.js 14 (App Router) + TypeScript + Tailwind CSS
- Supabase: Postgres، Auth، Realtime
- Vercel للاستضافة

## الإعداد المحلي

```bash
npm install
cp .env.local.example .env.local   # ثم عبّي القيم كما بالأسفل
npm run dev
```

### متغيرات البيئة

| المتغير | من أين |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Settings → API |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase → Settings → API |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API → **service_role** (سري، لا يُنشر أبداً — يُستخدم فقط بمسارات السيرفر `/api/*` لإنشاء الحجوزات/الانتظار متجاوزاً RLS) |

نفس الثلاثة يجب إضافتها كمتغيرات بيئة على Vercel قبل النشر.

### مشروع Supabase

المشروع الحالي المرتبط بحساب المستخدم كان يحتوي مسبقاً على جداول تطبيق آخر غير مرتبط (تريفيا/مدفوعات). بما أن الحساب وصل للحد الأقصى للمشاريع المجانية (2)، تعذر إنشاء مشروع منفصل، فتمت إضافة جداول إفيكتو لنفس المشروع مع فصل كامل:

- كل الجداول مسمّاة بالبادئة `eficto_` (`eficto_customers`, `eficto_tables`, `eficto_reservations`, `eficto_waitlist`, `eficto_reviews`) لتفادي أي تعارض مع جداول التطبيق الآخر.
- Row Level Security مفعّل على الجميع: الإدارة (مستخدم مسجّل دخول عبر Supabase Auth) لها صلاحية كاملة، والزوار (anon) لهم قراءة فقط على `eficto_reviews` و`eficto_waitlist` (بدون بيانات شخصية بهذا الجدول — الاسم/الجوال بجدول العملاء المنفصل وغير مسموح للزوار).
- الكتابة العامة (حجز جديد، انضمام لقائمة الانتظار) تمر عبر مسارات `/api/*` بمفتاح `service_role` على السيرفر فقط، وليس مباشرة من المتصفح.
- إن رغبت لاحقاً بمشروع Supabase مستقل، يمكن نقل نفس ملف الـ SQL (راجع سجل المحادثة أو اطلب تصدير الـ schema) إلى مشروع جديد وتحديث متغيرات البيئة فقط.

### إنشاء أول مستخدم إدارة

لا يوجد تسجيل عام للوحة التحكم عمداً. لإنشاء أول حساب دخول:

1. Supabase Dashboard → Authentication → Users → Add user
2. أدخل البريد وكلمة مرور قوية، وفعّل "Auto Confirm User"
3. سجّل الدخول من `/admin/login` بنفس البيانات

## البنية

```
src/
  app/                 صفحات عامة + /admin (لوحة تحكم) + /api (مسارات الحجز/الانتظار)
  components/          مكونات الواجهة العامة + components/admin للوحة التحكم
  lib/                 عملاء Supabase، منطق توفر الطاولات، تنسيق التاريخ، ثوابت الموقع
```

## ملاحظات تصميم مهمة

- **الصور**: لا تتوفر صور فعلية للمطعم بهذه الجلسة، فتم استخدام مشاهد تجريدية (`ArchScene`) مبنية بـCSS/SVG تحاكي الأقواس والإضاءة الدافئة بدل صور ستوك عامة، التزاماً بتوجيه البرومبت. لاستبدالها بصور فعلية: أضف الصور إلى `public/images/` واستبدل مكونات `ArchScene` في `src/components/` و`src/app/*/page.tsx` بعناصر `<Image>`.
- **الشعار**: علامة بيضاوية بدوائر متداخلة (`src/components/Logo.tsx`) مبنية كاستلهام من الوصف النصي بالبرومبت (دوائر متوازية بشكل بيضاوي) وليست الشعار الفعلي — استبدلها بملف SVG الحقيقي عند توفره.
- **الخطوط**: Playfair Display (إنجليزي/الشعار)، Noto Naskh Arabic (عناوين عربية)، IBM Plex Sans Arabic (نصوص عربية).
- أدوات التصميم الخارجية (Figma/Adobe/Canva/Magic Patterns) لم تُستخدم بهذه الجلسة لعدم وجود أصول تصميم فعلية (صور/شعار) لاستيرادها أو تحويلها.

## أمان (npm audit)

المشروع مثبّت على `next@14.2.35` وهو الفرع الأحدث المرقّع أمنياً من Next 14 (tag `next-14` الرسمي من Vercel)، بدل القفز لـNext 16 (تغييرات جذرية بالـAPI قد تكسر الكود الحالي). قد يستمر `npm audit` بإظهار تحذيرات لأن نطاقات الإصدارات بقاعدة بياناته لا تفرّق دائماً عن فروع الـbackport؛ يُنصح بمتابعة تحديثات `next-14` دورياً.
